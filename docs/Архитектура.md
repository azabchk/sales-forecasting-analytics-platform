# Архитектура решения

## Компоненты
1. **Data Layer**: сырые файлы `train.csv`, `store.csv`.
2. **ETL Layer**: очистка/нормализация, загрузка в DWH.
3. **DWH Layer (PostgreSQL)**:
   - `dim_store`
   - `dim_date`
   - `fact_sales_daily`
   - KPI views (`v_kpi_summary`, `v_sales_timeseries_daily`, `v_sales_timeseries_monthly`, `v_top_stores_by_sales`, `v_promo_impact`)
4. **ML Layer**:
   - feature engineering
   - time split
   - обучение Ridge + CatBoost
   - сохранение артефактов
5. **Service Layer (FastAPI)**:
   - REST эндпоинты `/api/v1`
   - SQL-запросы к витринам
   - прогноз через модель
6. **Presentation Layer (React TS)**:
   - Overview
   - Store Analytics
   - Forecast

## Поток данных
```text
Kaggle CSV -> ETL -> PostgreSQL (звезда + views)
                         |-> FastAPI (KPI API)
                         |-> ML train (features + models)
ML artifacts -> FastAPI /forecast -> React UI
```

## Технические решения
- **СУБД:** PostgreSQL 16
- **Backend:** FastAPI + SQLAlchemy
- **ML:** scikit-learn + CatBoost
- **Frontend:** React + TypeScript + Vite + Recharts
- **Оркестрация БД:** docker-compose

## Нефункциональные требования
- Повторяемость (идемпотентный ETL)
- Безопасность (секреты только через `.env`)
- Расширяемость (добавление новых KPI views и ML-фич)
